# Signalbot — аудит готовності TradingView → BingX

Ця версія **НЕ відкриває** реальних ордерів за ідеями TradingView. Вона додає детерміноване рішення про придатність сигналу та план 80/20, не видаючи AI-аналіз за підтверджене виконання.

## Готово

- Для кожної нової AI-ідеї повідомляється вік публікації, актуальність, і причина, чому угоду не відкрито.
- Якщо є одна авторська ціль, TP1 = середина між ENTRY і ціллю автора (80%), TP2 = ціль автора (20%). Обчислений рівень **не є порадою автора**.
- Якщо автор указав два TP, використовується його TP1/TP2.
- Пропускаються ідеї, опубліковані більше 20 хв тому, закриті автором, без ENTRY/SL/TP, із непридатною ціною та недоступними контрактами.
- `split_quantity(total, precision, min_qty)` дозволяє відхилити розділення на 80/20, якщо один вихід менший за мінімум контракту.
- Перевірки працюють без обов'язкового live-ключа BingX; ринкові котирування — публічні.

## Потрібно перед реальними ордерами

Поточний `BingX.open_futures` створює **один** ордер з одним TP і SL. Для підтвердженої роботи 80/20 потрібні: створення двох незалежних захищених виходів з правильним positionSide, округлення за кроком кількості/ціни, підтвердження FILLED/часткових FILLED, перевірка фактичного захисту на біржі, ідемпотентність після рестарту, контроль відкритої позиції та обробка невдач другого ордера. Ця реалізація у ZIP **відсутня**. Не переводити TradingView-торгівлю у live на підставі повідомлення `READY_FOR_MANUAL_ORDER_TEST`.

## Інсталяція

Скопіювати змінені файли проєкту, запустити `python -m unittest discover -s tests -q`, потім виконати git commit/push і Railway deploy. Не завантажувати `.env`, Telegram `.session`, SQLite з секретами.
