# TradingView → BingX LIVE (експериментальна версія)

**УВАГА:** цей код надсилає справжні ордери. Локальні тести не перевіряють поведінку BingX під час часткового виконання або одночасного спрацювання SL і TP. Перед запуском перевір API-права, баланс і Hedge Mode. Починай лише з розміру позиції, втрату якого можеш прийняти.

## Railway Variables

```
TRADING_MODE=live
BINGX_LIVE_ACK=I_UNDERSTAND_REAL_ORDERS
TV_LIVE_EXECUTION=YES
TV_LIVE_ACK=I_ACCEPT_TWO_REAL_ORDERS
TG_LIVE_EXECUTION=NO
TV_FULL_REVIEW_ENABLED=1
TV_FULL_REVIEW_LOOKBACK_HOURS=1
```

Всі 4 opt-in змінні потрібні, щоб TradingView міг створювати реальні ордери. `TG_LIVE_EXECUTION=NO` не дає старому Telegram pipeline відправляти одноцільові ордери випадково. `TV_LIVE_EXECUTION=NO` негайно вимикає нові TradingView входи після redeploy (існуючі ордери НЕ скасовуються автоматично).

## Як працює

* Лише **нові**, не кешовані Gemini ідеї, не старші ніж `validator.max_age_minutes` (20 хв за поточним config.toml); рівні повинні пройти перевірку поточної ціни та контракту.
* Лише Hedge Mode. Якщо вже є відкриті ордери чи позиції цього символу — пропуск.
* Ризик/маржа/плече — з `config.toml`; мінімум контракту застосовується окремо до кожної частини.
* Якщо автор дав одну ціль, TP1 — середина між ENTRY і TP автора, TP2 — сам TP автора. Для двох цілей використовуються авторські TP1 та TP2.
* Надсилаються **два незалежні BingX MARKET/LIMIT входи**: 80% та 20%. До кожного запиту додаються `stopLoss` і `takeProfit` в нативному форматі BingX. Це *не* гарантує, що біржа коректно встановить/збереже обидва умовні виходи; перевір окремо в застосунку BingX.
* Запит записується в SQLite **до першої відправки**. Неоднозначний результат / timeout не повторюється автоматично. Другий ордер може не пройти, навіть якщо перший уже прийнято — це стан `MANUAL_RECONCILIATION`.
* Статус `PENDING_VERIFY` — **ще не FILLED**, а результати однієї швидкої перевірки order endpoint не підтверджують спрацювання захисних TP/SL.
* Уже проаналізовані Gemini ідеї не відкриваються після зміни режиму та redeploy. Це спеціальний захист від старих сигналів; остання WLD-ідея не буде відкрита заднім числом.

## Перевірка прийнятих заявок

```bash
railway ssh
python /app/tv_live_audit.py
```

Звір ордери й SL/TP у BingX UI. При `MANUAL_RECONCILIATION` або відсутніх захисних виходах негайно керуй позицією вручну на біржі. Скрипт нічого не змінює.

## Відкат

В Railway зміни `TV_LIVE_EXECUTION=NO`, redeploy. Це не закриває існуючі позиції/ордера. Самостійно перевір їх у BingX.
