# Діагностика TradingView -> BingX

Патч додає у **нові** AI-сповіщення час від публікації, статус торгової готовності та причину, чому ордер не відкрито. Для однозначних USDT-криптовалютних пар він також читає доступність ф'ючерсу та ціну BingX через ПУБЛІЧНІ GET-запити (без API ключів).

`SKIP`: сигнал є аналізом, без ENTRY/SL/TP, непідтверджений ф'ючерс, неправильно розташовані рівні, чи ціна вже пройшла TP/SL.

`CHECK`: потрібно підтвердити контракт або ціну на біржі.

`READY_FOR_EXECUTION_CHECK`: лише ринкова перевірка пройдена. **Це не означає, що угода відкрита.** Автоматичний виконавець TradingView і TP 80/20 ще відсутні.

Для однієї авторської цілі можлива лише ілюстрація TP1 = середина ENTRY↔TP автора, TP2 = TP автора. Бот не надсилає ці розраховані цілі на біржу.

Час публікації визначається з публічного API TradingView. Старі AI-огляди залишаються кешованими; для повторного аналізу використай `--force` (додаткові витрати Gemini). Автосканер додає статус новим, ще не кешованим ідеям.

Не встановлюй `TRADING_MODE=live` з розрахунку, що це ввімкне торгові ордери TradingView: поточна реалізація відправляє лише повідомлення. Автоторгівля потребує окремої реалізації звірки фактичних виконань LIMIT, двох reduce-only TP і SL.
