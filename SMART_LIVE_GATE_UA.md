# Signalbot: Smart Entry як обов'язкова перевірка LIVE

## Що змінилося
`tv_live_engine.execute` тепер не може надіслати ордери BingX, поки `TV_SMART_ENTRY_LIVE_GATE=YES` не встановлено. Це свідомий fail-closed режим навіть за наявності `TRADING_MODE=live`, `TV_LIVE_EXECUTION=YES`.

Після активації кожна спроба LIVE-входу **заново** викликає Smart Entry (`tv_smart_entry.inspect`) на свіжих закритих свічках BingX:
- WAITING: відстань до зони входу велика; ордер заборонено;
- CONFIRMING: немає підтверджувальної закритої свічки; заборонено;
- CHECK: невідомий TF, недостатньо даних або технічна помилка; заборонено;
- INVALID: сценарій не відповідає вимогам; заборонено;
- READY_REVIEW: **дозволяє перейти до решти перевірок**, але не гарантує ордер.

Інші перевірки лишилися: вік і TF, публічна ціна, доступність контракту, перевірка історії для старих ідей, авторське закриття, Hedge Mode, наявні ордери й позиції, мінімум біржі, доступний капітал та SQLite ідемпотентність.

## Встановлення
З Mac у каталозі `tg`:
```bash
unzip -o ~/Downloads/signalbot-smart-live-gate.zip -d .
python -m unittest discover -s tests -q
git add -A
git commit -m "Require fresh Smart Entry approval for TradingView LIVE"
git push origin main
railway up
```

## Активація
За замовчуванням **нові LIVE-ордери блокуються**. Щоб явно увімкнути новий контрольований LIVE, встановити у Railway Variables:
```env
TRADING_MODE=live
TV_LIVE_EXECUTION=YES
TV_SMART_ENTRY_LIVE_GATE=YES
TV_SMART_ENTRY_ENABLED=1
```
Після збереження застосувати новий deploy. Інші чинні підтвердження (`TV_LIVE_ACK`, `BINGX_LIVE_ACK`) залишаються потрібними.

## Дуже важливо
- Це **не перевірка на реальній біржі**. Тести використовують моки. Обидва прив'язані TP/SL BingX досі не були фактично перевірені для виконаної позиції.
- `READY_REVIEW` — проста евристика відскоку ціни за закритою свічкою, а не AI-підтвердження змісту авторського сценарію.
- Цей патч не керує вже відправленими LIMIT-ордерами і не скасовує їх. Він перевіряє тільки **перед новими входами**.
- Старі сигнали, що вже перебувають у кеші, не отримають автоматичний ордер без запуску окремого `tv_live_catchup.py` та проходження всіх перевірок; ця команда може викликати реальні ордери.
- Для швидкого блокування **нових** TradingView входів змінити `TV_SMART_ENTRY_LIVE_GATE=NO` або `TV_LIVE_EXECUTION=NO`, застосувати deploy. Це не закриває наявні позиції.
- Не запускати 16-годинний catch-up одразу після LIVE-активації: спочатку перевірити ордери в BingX і `python /app/tv_live_audit.py`.
